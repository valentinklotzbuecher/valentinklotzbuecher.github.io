R and Quarto: a short start

Set up a project, learn the R you need first, and let Quarto turn code and text into reports, slides and theses.

This page grew out of the software tutorials of a seminar I taught at the University of Freiburg in the 2024/25 winter term, Reproducible research pipelines with R and Quarto. In it, Master’s students in economics took conflict event data from the raw files to clean data, maps, estimates and a finished report. What is useful beyond the seminar is kept here, rewritten as a short start.

It is for former participants who want to look something up, for anyone I have sent here, and for anyone who has just finished an R course and wants to write a first report in Quarto. If that is you, skip ahead to Quarto.

Why work this way

A reproducible pipeline means that every number, table and figure comes from code, and that one command rebuilds the whole document from the raw data:

raw data → R code → Quarto document → web page · Word · PDF · slides

Three habits follow from it:

  • Never edit data by hand. Keep the raw files as you got them and make every change in code.
  • Never copy a result into the text. Numbers, tables and figures are computed where they appear.
  • Keep everything in plain text. Scripts and Quarto files are text, so version control with Git can track every change.

The pay-off comes the second time round: when the data are updated or a referee asks for another specification, you rerun instead of redo, and text and results cannot drift apart. Plain text also suits coding agents, which can read, run and change a project like this.

Set up once

  1. Install R, an editor and Quarto. RStudio Desktop is the usual editor and comes with Quarto; Positron is Posit’s newer one. A separate Quarto install keeps Quarto up to date.

  2. Make one folder per project. In RStudio, File › New Project creates the folder and an .Rproj file; open the project by double-clicking that file. R then starts in the project folder, so every path can be relative to it and the project runs on any computer:

    my-project/
├── my-project.Rproj
├── data/             raw data, never edited by hand
├── report.qmd        text and code
└── references.bib    bibliography
    births <- read.csv("data/births.csv")    # relative path: works anywhere
# setwd("C:/Users/me/Desktop/project")   # works only on your computer

  3. Start each session clean. Under Tools › Global Options › General, untick Restore .RData into workspace at startup and set Save workspace to .RData on exit to Never. Restart R now and then (Session › Restart R) and run your code from the top: if it still works, your results come from your code and not from objects left over in memory.

  4. Install a package once, load it in every script. install.packages("dplyr") downloads a package, library(dplyr) loads it. If you need to rerun a project years later, renv records the package versions it used.

The R you need first

The best free introduction is R for Data Science (Wickham et al. 2023), the seminar’s main reference. This section runs one small pipeline on data that come with R, so you can paste each step into the R console and get the same result.

Clean

library(dplyr)

births <- birthwt |>
  mutate(
    smoker    = factor(smoke, levels = c(0, 1), labels = c("No", "Yes")),
    weight_kg = bwt / 1000,
    mother_kg = lwt * 0.4536
  ) |>
  select(weight_kg, smoker, age, mother_kg)

head(births, 3)
   weight_kg smoker age mother_kg
85     2.523     No  19   82.5552
86     2.551     No  33   70.3080
87     2.557    Yes  20   47.6280

The pipe |> hands the result of one step to the next: take birthwt, then add variables with mutate(), then keep four of them with select(). Turning a 0/1 code into a labelled factor makes every table, figure and model that follows easier to read.

Summarise

births |>
  group_by(smoker) |>
  summarise(n = n(), mean = mean(weight_kg), sd = sd(weight_kg)) |>
  knitr::kable(digits = 2)

group_by() and summarise() compute statistics by group, and knitr::kable() formats the result as a table, Table 1. For tables ready for a paper, see gtsummary, common in medicine, and modelsummary, common in economics.

In these data, babies of mothers who smoked weighed on average 269 g less than babies of mothers of the same age and weight who did not smoke. That number is not typed into this page: inline code in the page’s source computes it, so it would change with the data. Whether it is the effect of smoking is a question of research design, not of code; Huntington-Klein (2021) is a readable introduction to causal inference with observational data.

Quarto

Quarto turns a plain-text file that mixes text and code into a finished document. A .qmd file has three parts: a header between two --- lines, written in YAML; text, written in Markdown; and code chunks, which run when the document is rendered. Here is a complete report built from the pipeline above. Save the two files in one folder and render the first:

report.qmd
---
title: "Smoking and birth weight"
author: "Your Name"
date: today
format:
  html: default
  docx: default
  typst:              # PDF, without installing LaTeX
    citeproc: true    # cite as in HTML and Word
bibliography: references.bib
execute:
  echo: false
---

```{r}
#| include: false
library(MASS)       # contains the data set birthwt
library(dplyr)
library(ggplot2)

births <- birthwt |>
  mutate(smoker    = factor(smoke, levels = c(0, 1), labels = c("No", "Yes")),
         weight_kg = bwt / 1000)

fit <- lm(weight_kg ~ smoker, data = births)
diff_g <- round(-1000 * coef(fit)[["smokerYes"]])
```

Render

  • In RStudio, click Render (Ctrl/Cmd + Shift + K); in Positron, Preview.
  • In a terminal, quarto render report.qmd makes all three formats in the header, quarto render report.qmd --to docx makes only the Word file, and quarto preview report.qmd renders again each time you save.

The same file becomes a web page, a Word document and a PDF, each with Table 1, Figure 1, the numbers in the text, the citation and the list of references in place.

What each part does

  • Header. Title, author, date, the output formats and their options, the bibliography. echo: false hides the code in the output, which suits a report; leave it out for a tutorial like this page.
  • Chunk options. Lines starting with #| set options for one chunk: include: false runs the chunk but shows nothing, label names it, and fig-cap and tbl-cap add captions.
  • Inline code. `r nrow(births)` writes the number of births into the sentence; when the data change, the text changes with them.
  • Cross-references. A chunk labelled fig-… becomes a numbered figure and one labelled tbl-… a numbered table; @fig-weight in the text becomes “Figure 1”, with a link in the web page. Equations and sections work the same way (more).
  • Citations. [@hosmer1989] cites the entry with that key in references.bib, and the list of references goes at the end. Reference managers export .bib files; for Zotero, the Better BibTeX plugin keeps the file in sync. A citation style such as csl: apa.csl sets the format.

One source, many formats

Each of the seminar’s four assignments used another format; together they cover most of what you need:

Format In the header Good for
Web page html sharing as a link, or as one file with embed-resources: true
Word docx co-authors who edit in Word; reference-doc applies your template
PDF typst, or pdf papers and theses; pdf uses LaTeX, installed once with quarto install tinytex
Slides revealjs talks: each ## heading starts a new slide

Larger projects are websites, like this one, and books, like my thesis template; manuscripts bundle a paper with the notebooks behind it. When code takes long to run, freeze keeps its results until the code changes (more).

Practise

The seminar’s assignments make a good path through your own data, or through one of the data sets that come with R (data() lists them):

  1. A web page with a few of the data steps above and two or three references.
  2. A PDF with a figure and a table, both cross-referenced in the text.
  3. Slides with an interactive figure or table, made for instance with plotly or DT.
  4. One source, three outputs: the same file as web page, PDF and Word.

Going further

The seminar’s topics, and where to continue:

  • R and cleaning data: R for Data Science, above all its chapters on tidy data, joins, factors and dates. The Big Book of R lists hundreds of free books on R.
  • Figures: the ggplot2 extensions gallery, and Vincent Arel-Bundock on consistent figures in Quarto.
  • Maps and georeferenced data: Geocomputation with R.
  • Effects and research design: The Effect (Huntington-Klein 2021) and Scott Cunningham’s Causal Inference; Carlisle Rainey on equivalence tests, for arguing that an effect is negligible rather than merely not significant.
  • Workflow: What They Forgot to Teach You About R on projects and paths, Happy Git and GitHub for the useR on version control, and Frank Harrell’s R Workflow for reproducible clinical research. LSE’s Data for Data Scientists is a full course.
  • More Quarto: Emil Hvitfeldt’s Slidecraft 101 on slides, Cameron Patrick’s PDF formatting tips for theses, and a guide to effect sizes and confidence intervals written as a Quarto book.
  • Statistics: Richard McElreath’s Statistical Rethinking lectures.
  • A thesis topic that matters: Effective Thesis.

Once this workflow feels familiar, much of the routine can be handed to an AI agent: see Coding agents with GitHub.
